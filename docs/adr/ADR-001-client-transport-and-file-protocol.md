# ADR 001 客户端传输与文件协议

## 状态

已接受，适用于协议版本 1.0。

## 背景

Windows 客户端只连接应用服务器。协议需要支持低延迟消息、受控文件传输、统一认证，
同时不能向客户端暴露 RabbitMQ 或 PostgreSQL。

## 决策

- 消息入口采用 `WSS /ws`。每个文本帧只能包含一个 UTF-8 JSON 对象，初始上限为
  64 KiB。服务端先检查帧字节数，再解析 JSON；超限请求以 `LIMIT_EXCEEDED` 结束。
- 文件内容采用 `HTTPS PUT/GET /api/files/{fileId}/content` 流式传输。WSS 与 HTTPS
  使用同一服务器域名、应用入口和 TLS 证书，文件二进制不进入 WSS 或 RabbitMQ。
- 公网只开放经批准的 TLS 应用端口。RabbitMQ 5672、15672 和 PostgreSQL 5432
  继续绑定服务器回环地址。
- 服务端会话是发送者身份的唯一权威来源。匿名注册、登录和恢复请求的 `senderId`
  必须为 `null`；其余客户端请求的 `senderId` 必须与已认证会话一致。
- 客户端时间只作诊断输入。服务端接收信封时使用自身 `Clock` 生成权威 `timestamp`。
- PUT 必须携带准确的 `Content-Length`。同一 `fileId` 重试时，服务端先清理旧临时文件
  并从零写入，禁止追加旧字节；完成后校验大小与 SHA-256，再原子移动到最终位置。
- 每次 PUT 和 GET 都独立校验会话、文件参与者、状态和授权期限。下载名称由净化后的
  展示元数据生成，服务端存储键和路径不进入响应。

## 后果

客户端只需管理一套 TLS 信任和应用凭据。消息与文件可以分别设置容量、超时和取消策略，
服务端也能在进入业务层前统一校验版本、身份和负载。部署时必须保证基础设施端口不对公网
开放，并让反向代理或应用服务器在解析 JSON 前执行 64 KiB 帧限制。

## 回退方式

如 WSS 实现无法满足 Windows 客户端兼容性，可在新的 ADR 中选择同域名下的 HTTPS
长轮询；协议信封与文件接口保持不变，旧入口在一个兼容期后下线。
